# Building and publishing a Fibo release

1. Check the source with `python -m pytest -q` and `python scripts/check_release.py`. Review the asset revisions, hashes, model license and intended noncommercial use.
2. Push reviewed source to `akhilsivanand/fibo-runpod` and dispatch `.github/workflows/container.yml` on that source revision. The workflow builds once, checks Python/native dependencies, starts CPU ComfyUI to verify nodes and template routes, and pushes `ghcr.io/akhilsivanand/fibo-comfyui:staging-<commit>`. This dedicated registry package is public; no shared MOSS repository workflow is needed.
3. Verify the resulting image digest is anonymously pullable. Deploy that exact digest to a task-owned Runpod Pod. Re-read the effective GPU rate, driver and storage settings. Do not duplicate paid deployments during retries.
4. Run an actual source-image edit through ComfyUI, inspect the output, and record dimensions and duration. Verify authenticated HTTP and WebSocket traffic through the public Runpod proxy, then restart and verify retained models, user files and workflows. Test the queue handler using a fresh worker with the same image.
5. Record only observed facts in `docs/validation.json`: package version, source revision, image digest, UTC validation timestamp, GPU details, Pod authentication/fresh-volume/restart flags, and one completed `edit` job for both Pod and Serverless. Each image record needs dimensions and SHA256. Deployment-specific IDs, service credentials and user images belong outside the source package.
6. Promote only the GPU-tested manifest to `ghcr.io/akhilsivanand/fibo-comfyui:0.1.0`, verify anonymous access and digest equality, and put the tested immutable digest in `deploy/pod-template.json`. Run `python scripts/check_release.py --publish`. Create a deterministic source archive with `python scripts/package_release.py` outside the repository. A source-only archive is allowed before GPU validation but must be described as unvalidated.
7. Publish the tested Pod template. Create a GitHub release and submit the repository through Runpod Hub's normal maintainer flow. Hub indexes releases and builds/tests them before manual review. Confirm each state separately; a push, release, or accepted submission is not approval.

The source package contains no commercial-use grant for Fibo weights. Runpod submission metadata must preserve the noncommercial limitation and Bria licensing link. The previous MOSS listing encountered a provider-side source-download HTTP 401; diagnose any new build using its own result rather than assuming that issue is resolved.

The 0.2.0 base is the immutable GPU-tested Fibo 0.1.0 image, preserving its Python 3.11, PyTorch 2.13/CUDA 13, ComfyUI and inference dependencies. Its lineage retains the original MOSS dependency base and Runpod initialization. Rebuilding a new image or changing native dependencies requires fresh inference checks; MOSS's historical GPU results are not Fibo evidence.

## Standard service ports in 0.2.0

Use ComfyUI on 8188, JupyterLab on 8888, FileBrowser on 8080 and SSH on 22. Jupyter uses the native token; it is an actual Jupyter service rather than a replacement ComfyUI gateway. ComfyUI retains token protection on 8188 through its token login page, with FIBO_PASSWORD Basic authentication available as an alternative. The internal model backend remains private on 8189. The host/container port declarations, Connect labels and actual listeners must agree.

The historical 0.1.0 GPU report is now `validation-0.1.0.json`. A CPU service test establishes port routing and service startup only. Do not describe it as a fresh GPU inference or restart-preservation test. No new GPU resource is required to correct and test these service ports; the stopped personal Pod is deleted at the user's request after publication of the corrected configuration.
